# ドキュメントの書き方

システムの設計・実装を説明するドキュメント（`docs/` 配下、ルート `CLAUDE.md` 等）に何を書き、何を書かないかを定める。

これらの文書は実装が変わっても揺らがない粒度で書く。
設計の意図・不変条件・根拠・トレードオフを主に記述し、実装コードやテストコードが所有する揮発的な具体は、それらを唯一の情報源として扱う。

本ルールを適用する際は `writing-style.md` も併せて読む。

## ルール一覧

### 揮発的な具体はコード・テストを出典として参照する

定数値・エンドポイント・型のフィールドなど、コード変更で陳腐化する具体に言及するときは、出典となるファイルやシンボル（実装コードまたはテストコード）を併記する。
出典のない裸の値は書かない。
値の一致はコード・テスト側で担保し、文書は設計上の意味づけを担う。

網羅的な列挙（全設定項目の逐語コピー・型の全フィールドの転記等）は、設計理解に不可欠な範囲に絞る。
単なる転記はコードに委ね、参照で代替する。

NG（出典のない裸の値）:

```markdown
最低滞在時間の初期値は 600 秒。
```

OK（出典を併記する）:

```markdown
最低滞在時間はサーバ設定 `minimum_stay_duration`（`setting-defaults.ts` の既定値）で決まる。
```

### 実装済みと将来構想を分離する

実装済みの記述と未実装の設計は節を分け、将来構想であることを明示する。
読み手が現状の実装と検討中の設計を取り違えないようにする。
