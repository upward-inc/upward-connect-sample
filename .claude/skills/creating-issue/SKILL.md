# Issue の起票

UPWARD Connect チームの Linear に Issue を起票する。

## 前提

- Linear MCP サーバー（`linear-server`）が接続・認証済みであること
- チーム識別子: `UC`
- Linear MCP 経由ではテンプレートを取得できないため、Linear 側のテンプレートと同等の内容をこのスキル内の「テンプレートガイド」に重複定義している。Linear 側のテンプレートを変更した場合はスキルも合わせて更新すること

## 実行フロー

1. 「テンプレート選択の基準」に従い `get_document` で選択基準を取得し、Issue 種別に最も適合するテンプレートを選ぶ
2. `list_issue_labels` でラベル一覧を取得し、タイトル・説明文・ラベルを決定する（`Type` はテンプレートと1:1で対応するものを、`Type` 以外は文脈に合うものを選ぶ）
3. 会話の文脈に参考リンクがあれば `links` フィールドに設定する
4. 下書きをユーザーに提示して確認を取る（ラベルは名前で表示する）
5. 承認後、ステップ2で取得済みのラベルIDを使って Issue を作成する

## タイトルの規則

- 1 行で簡潔に
- 目的・現象を端的に表す（例: 「〜を追加する」「〜を改善する」「〜できない」「〜の脆弱性を修正する」）

## テンプレートガイド

テンプレートガイドのセクション名を `##` 見出しとして使い、説明に従って内容を記入する。
必須セクション（YES）は文脈から積極的に埋め、任意セクション（NO）は書く情報がなければ見出しだけ残す。

記入時の形式ルール（文章スタイルは `.claude/rules/writing-style.md` に従う）：

- 長文の散文は避け、箇条書きとインデントで構造化する
- 実装手順は概要レベルにとどめる（What・Why を主軸に置き、How を書きすぎない）
- チェックボックスリスト（`- [ ]`）は使わない
- ファイルパス・コマンド・コード識別子はインラインコード（バッククォート）で囲む
- Linear は本文中の Issue ID を「ID + タイトル」に展開するため、1 文に ID を連続・反復すると可読性が下がる。連続使用を避け、複数挙げるときは例えばバレットに逃すとよい
- 本文中で PR 番号など、URL を伴わない短縮識別子を記載する場合は Markdown リンク形式で書く（例: `[#589](https://github.com/upward-inc/upward-connect-internal/pull/589)`）
  - 識別子だけの記述はクリック可能なリンクにならないため、参照先へ辿れるよう明示的にリンク化する
  - URL をそのまま貼ること自体は問題ない

Issue ID の書き方（NG / OK）:

- NG（1 文に ID を連続・反復）: 「backend の設定追加は UC-123、設定 UI は UC-124 が担当する。UC-123 完了後に frontend 対応へ着手し、UC-124 と文言を揃える」
- OK（例: バレットに逃す）:
  - 各設定の担当:
    - UC-123（backend の設定追加）
    - UC-124（設定 UI）

### テンプレート選択の基準

Type は同名の Issue Template に 1:1 で対応するため、テンプレート選択は Type の選択基準で判定する。
その基準は Linear ドキュメント「Issue Type 選択の基準」を単一の情報源とし、インラインには定義しない。
スキル実行時に `get_document`（slug: `issue-type-選択の基準-7fc724e9e02f`）で取得し、基準表と各境界の判定ルールに従ってテンプレートを選ぶ。

| セクション                  | 説明                                                    | 必須 |
| --------------------------- | ------------------------------------------------------- | ---- |
| 実装の説明（What）          | この Issue で実現する機能の目的・背景・技術的アプローチ | YES  |
| 実装を行う理由や経緯（Why） | この機能に取り組む背景・課題・ビジネス上の動機          | YES  |
| 完了の定義（DoD）           | この Issue が完了したとみなす条件・受け入れ基準         | YES  |
| 補足                        | 懸念点や制約等の補足情報                                | NO   |
